# Vakaman Studio Protocol

## 1. Work cycles
Every production cycle follows:
Creative Intent → Interaction Specification → Physical Model → Technical Architecture → Implementation → Visual Review → Quality Review → Integration.

## 2. Handoff contract
INTENT / OBSERVATIONS / DECISIONS / CHANGES or PROPOSALS / VERIFICATION / RISKS / NEXT HANDOFF.

## 3. Evidence rule
Statements about the repository must come from inspection. Statements about the client must come from supplied/verified source material. Statements about performance must include measurements or clearly labeled estimates. Statements about creative quality are recommendations, not facts.

## 4. Conflict resolution
1. Preserve business clarity.
2. Preserve user comprehension and accessibility.
3. Preserve brand distinctiveness.
4. Preserve technical maintainability.
5. Optimize performance.
6. Only then add extra flourish.

When a conflict remains, Director decides and records the trade-off.

## 5. Failure modes to hunt
Generic luxury template; hover-only navigation; gratuitous WebGL; visual spectacle before content; unbounded pointer physics; mobile as a shrunken desktop; hidden CTAs; fabricated project claims; unmeasured GPU effects; giant page components; dependency sprawl; inaccessible custom controls; slow first paint; animation that hijacks scrolling; asset provenance loss.

## 6. Definition of done
A feature is done when it works, is responsive, is accessible, survives interruption, has a fallback, is tested, is performant enough for its target tier, and is documented well enough for the next agent to maintain.
